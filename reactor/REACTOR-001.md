# REACTOR-001 — Recursive Plan Compiler (planZ owner)

**Status: working draft / proposal-only, dependent on BANANAS-001 PR #19 and its unmerged conversation-harvest parent PR #18.** This is not a live autonomous agent, accepted project plan, genuine field outcome, or connected native engine runner.

## What becomes executable

The existing original BANANAS-001 compiler builds eight source-linked, quarantined mission chambers from 64 provisional conversation leads. REACTOR-001 consumes **that actual compiled output**, verifies its digest and eight-chamber held status, and constructs a finite, immutable directed acyclic graph:

    eight source chambers (exact BANANAS-001 output digest)
        │
        ├─ ABSENCE  — Static Workbench: remove an assumed port; preserve obstruction
        ├─ TIME     — Static Live: return later as a separately identified occurrence
        ├─ CARRIER  — STATIC OS: ask what survives an offline/change-of-machine carrier
        └─ RECEIVER — Static Field: independent HOLD/REFUSE without rewriting origin
        │
        └─ four saved, independently addressed "angle cuts" per source
               └─ ONE new held synthesis proposal per source
                       ↳ these become the input plans for the NEXT round

Round one additionally discovers bounded cross-chamber bridge candidates **only when two chambers share exact harvested plan IDs**. Shared plan ancestry is not proof of real project compatibility, interface ports, performance readiness, source rights, cooperation, or permission.

The compiler is deterministic. Its "new ideas" are **typed procedural counterfactuals and new cross-plan experimental questions**, *not* model-generated understanding of all repository bodies. It does not invoke Static Workbench, Static Live, STATIC OS, Static Field, GRAFT, CANNON or JAR;VIS. Their relevant laws informed the four lenses. Any true native adapter must be proven separately and may refuse.

## Run

Requires Node 20+ and the unmerged BANANAS-001 branch ancestry, with its original 64-line harvest input and eight chamber recipe.

    node --test reactor/collide.test.mjs reactor/recursive.test.mjs

    # Read-only derivation to stdout
    node reactor/recursive.mjs --depth 2 --cross-limit 4 --format md

    # Make each angle and new plan an independently inspectable immutable file
    node reactor/recursive.mjs --depth 2 --cross-limit 4 \
      --format json --out-dir ./held-reactor-run

An output directory contains:

    cuts/<content-address>.json
    proposals/<content-address>.json
    manifests/<sha256>.json

Existing files are never overwritten. Exact repetition is idempotent; tampered existing bytes cause refusal. The complete manifest lists source identities, ancestry, lens rules, parent IDs, generated plan IDs, and each generation's counts. Later runs with different depth or crossings create new manifest files rather than rewriting history. This is a **local file ledger**, not CANNON canon, reLATTE receiving-world authority, or a durable cloud service.

## Generation and restraint

- Depth: 1–3, default 2. No unbounded recursion, infinite agent loop, external search, background generation or uncontrolled job dispatch.
- First-round shared-lead crossings: 0–8, default 4. Subsequent rounds do not automatically invent new pairwise world crossings.
- Each round saves four distinct perspective cuts per input. Only source-linked, explicitly provisional compositions enter the next round.
- Source pointers and low-confidence UNKNOWN state remain visible. The compiler refuses digest mismatch, source promotion, duplicate identities and missing source data.
- The same input/parameters produce byte-identical manifests. Different parameters yield distinct, addressable manifests.
- Nothing in the output is self-executing, selected, admitted, published, or field-verified.

## Source-owner handoffs — *future* independent experiments

1. **Static Workbench:** A human might inspect a held ABSENCE cut as a MACHINE-CONJECTURE candidate. A failed concrete join should be preserved, not silently repaired.
2. **STATIC OS:** An operator might encode a CARRIER cut in a verified universal cartridge and replay it on a different machine. Source object verification and hardware/runtime acceptance remain original OS responsibilities.
3. **Static Live:** A TIME cut may seed a new Ghostcast delayed return, never impersonating the original performance or authorizing media use.
4. **Static Field:** A RECEIVER cut can become a voluntary tabletop encounter with distinct source-world and destination-world histories. A software-simulated refusal is not real-world consent.
5. **CANNON:** After an operator selects a particular proposal, a separate, explicitly authorized CANNON experiment could seek exact native owner source pins, test real interfaces, run one bounded composition and return cold-replayable receipts. planZ must not mark success from an intended orchestration alone.
6. **JAR;VIS / webZ:** A separate public-safe adapter could display reviewed choices and one-click use, without marketing held ideas as a published tool.
7. **GRAFT:** A successful, source-backed and owner-permitted return may become another candidate for the next census/research pass. No auto-adoption.
