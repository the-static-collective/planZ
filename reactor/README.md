# BANANAS-001 — 64-seed reactor

**Working branch / quarantined proposal.** This experiment depends on the unmerged 64-record conversation harvest. It does not change any plan's `disposition`, `confidence`, owner, branch admission, or evidence.

## Idea

The 64 seeds are not 64 tickets and not a 64-way project merger. They are **64 reusable candidate affordances** that can participate in multiple, explicitly unapproved compositions.

```text
64 quarantined conversation leads (provenance incomplete)
       │
       ▼
  8 overlapping chambers  ────────> 8 read-only candidate mission capsules
       │                               │
       │                  human selects one particular / one bounded pilot
       │                               │
       │                 owning project verifies source, rights and current code
       │                               │
       └──────────────> HOLD / REFUSE / real field test (external to reactor)
                                       │
                              optional return to Abundent
```

The present recipe map covers **all 64** distinct leads across **98 memberships**. **34** seeds appear in more than one chamber; overlap preserves ancestry rather than silently deduplicating it. Each chamber has 5–6 *core candidates* and additional *orbit possibilities*, not mandatory build dependencies.

## Zero-install compiler

Requires Node.js 20+ and a checkout containing the proposed harvest branch.

```bash
node --test reactor/collide.test.mjs
node reactor/collide.mjs --format md --out /tmp/banana-map.md
node reactor/collide.mjs --format json --out /tmp/banana-capsules.json
```

The JSON is shaped for a possible **read-only /today or /composer visitor interface**, not a deployment instruction. Both output formats include SHA-256 of the **exact source bytes** and the **exact recipe map**, so a changed harvest can be detected. Repeated runs from unchanged inputs reproduce the same output. The generator never fetches a URL or operates a project.

### Inputs

- `registry/conversation-plan-records-2026-10-16.jsonl` — 64 low-confidence, UNKNOWN, reconstructed conversation leads.
- `reactor/recipes-v0.json` — explicitly proposed thematic overlap, possible owner routing, smallest test, expected return and human/source gates.

### Outputs

- Eight source-linked proposed chains and optional orbit sets.
- A replay hash and coverage accounting.
- Gates that remain **unsatisfied**, regardless of visual presentation.
- No synthetic success, admission, deployment, publication, event or delivery claim.

## The bigger move: ONE PARTICULAR → MANY POSSIBLE RETURNS

Instead of showing a project index, Abundent's future **Day Engine** could accept *one owner-supplied particular* and let the person select a medium:

```text
source-linked song or story or question or public-safe need
       → Fossil Jukebox (hear)
       → Orchard Cinema / Rhythm Mutant (see or perform)
       → Roomship (cross)
       → Needful Porch (offer or ask)
       → Ghost Post / Traveling Jubilee (carry, if consented)
       → Mission Forge (preserve an unresolved edge)
       → voluntary return, without global adoption
```

These arrows are **possible human-directed transitions**, not automatic transfers. No particular must enter all chambers. One project may refuse a crossing without destroying the parent artifact.

### Typed boundaries for a later integration (not implemented)

**Source envelope:** exact ref/hash, source kind, authorized owner, rights and public-safe projection.

**Candidate score:** source digest, contributing plan IDs, chamber ID, inference/proposal marking, explicit missing gates; not an execution permit.

**Human selection:** one particular, chosen chamber, KEEP/HOLD/REFUSE; choosing an option is not evidence the option works.

**Owner receipt:** only the owning runtime/person may report a real test, source observation, acceptance or rejection, with independently inspectable evidence. It cannot be generated by this static combinator.

**Public return:** separate editorial review for Abundent display, separate opt-in for email, separate consent for any physical event or message delivery.

## First cross-chamber experiment

A permitted **single song identity** becomes an inspectable SIA ancestry card (M02/M04), a *proposed* Story DNA motif crossing (N06/N02), an editable lemonPRESS page (N07/V03), and an optional browser-safe listening invitation (/week / composer, W05/W02). A second human may choose a Ghost Post QR envelope (P08), but physical transfer is only real after a separate two-device witness. Every boundary must permit HOLD. This single pilot would test a new cross-project **ability to return to a source**, not just aggregate existing feature lists.

This is the suggested first cross-cut once an actual permitted track, owner intent, and current project branches are verified. It is **not** performed here.

## Explicit non-claims

The 64 records are not 64 verified futures, eight chambers are not eight implementations, overlap is not evidence of compatibility, and GitHub branches are not admission. Existing source summaries have incomplete chat provenance and were not upgraded. No raw transcripts, private media, customer data or sensitive user details enter this repository. No third-party copyrighted media is mirrored.
